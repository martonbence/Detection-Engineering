# T1003.004 — LSA Secrets

## Lényeg

A támadó a `HKLM\SECURITY\Policy\Secrets` alatt tárolt, a Local Security Authority által kezelt titkokat nyeri ki. Ez a hive tartalmazza a **szolgáltatásfiók-jelszavakat** (amelyeket a Windows automatikus bejelentkezéshez tárol, hogy a szolgáltatás rendszerindításkor emberi beavatkozás nélkül tudjon futni), az **automatikus bejelentkezési jelszót** (`DefaultPassword`, ha be van kapcsolva), **VPN és vezeték nélküli előre megosztott kulcsokat**, valamint **Domain Cached Credentials (DCC2)** hash-eket — ez utóbbi a [[T1003.005 - Cached Domain Credentials]] altechnikával fed át, mert ugyanaz az adat mindkét helyről kinyerhető.

A LSA Secrets kiemelt veszélye, hogy a benne tárolt jelszavak jelentős része **visszafejthető cleartextre**, nem csak hash formában — a Windows saját maga tárolja titkosítva, de a boot key (a SYSTEM hive-ból) birtokában a titkosítás megfordítható. Egy szolgáltatásfiók-jelszó gyakran domain-szintű jogosultsággal rendelkezik, így ez az altechnika közvetlen laterális mozgási vagy privilege escalation utat nyithat.

> [!quote] MITRE definíció
> Adversaries with SYSTEM access to a host may attempt to access Local Security Authority (LSA) secrets, which can contain a variety of different credential materials.

## Hogyan csinálják a gyakorlatban

A SAM ([[T1003.002 - Security Account Manager]]) kinyeréséhez képest a különbség csak a célhive: itt a `HKLM\SECURITY` a cél a `HKLM\SAM` helyett, a boot key-hez pedig ugyanúgy a `HKLM\SYSTEM` hive szükséges.

### reg.exe export/save

```powershell
reg.exe save HKLM\SECURITY C:\temp\security.hiv
reg.exe save HKLM\SYSTEM C:\temp\system.hiv
```

Ezt gyakran a PsExec `-s` flaggel indítják, hogy SYSTEM szintű `reg.exe`-t kapjanak SYSTEM shell megszerzése nélkül (Atomic Red Team T1003.004 Test #1) — ilyenkor a gyermek `reg.exe` parancssora mellett a PsExec launcher saját parancssora is tartalmazza a teljes `save`/`export` mintát.

### esentutl.exe /y

```powershell
esentutl.exe /y C:\Windows\System32\config\SECURITY /d C:\temp\security.hiv
```

A kimásolt `SECURITY` és `SYSTEM` hive-ból a titkokat offline fejtik: Impacket `secretsdump.py`, `pypykatz`, vagy Mimikatz `lsadump::secrets`.

**Mi váltja ki a gyakorlatban:** ugyanaz a mintázat, mint a SAM-nál — a leggyakoribb legitim előfordulás egy dokumentált incidenskezelési vagy forenzikus vizsgálat, illetve (ritkábban) hive-szintű biztonsági mentés, amely közvetlenül `reg.exe`-t vagy `esentutl`-t hív a natív backup API helyett.

## Mitigáció

- **Szolgáltatásfiókok kezelése Group Managed Service Account (gMSA)-val** — a gMSA jelszavát a Windows automatikusan, gyakran forgatja, és sosem tárolja emberi kézzel visszafejthető formában ugyanúgy, mint egy hagyományos szolgáltatásfiók jelszavát — ez a technika **hatását** csökkenti radikálisan, ha a zsákmány egy gMSA titka, mert az rövid életű
- **Automatikus bejelentkezés (`AutoAdminLogon`) tiltása** — megszünteti a `DefaultPassword` LSA Secret előfeltételét azokon a gépeken, ahol nincs rá szükség
- **A helyi admin jogok korlátozása** — a hozzáféréshez SYSTEM/admin szint kell, tehát ez az előfeltétel szűkítése, nem a technika megszüntetése

## Detekciós stratégia

### Szükséges telemetria

| Adatforrás                  | Típus   | Megjegyzés                                                        |
| ---------------------------- | ------- | -------------------------------------------------------------------- |
| Sysmon EID 1 (ProcessCreate) | Process | `reg.exe save/export HKLM\SECURITY`, `esentutl.exe /y` a SECURITY hive-ra |

### Detekciós logika

Ugyanaz a két szabály fedi a .004-et, mint a .002-t, mert a folyamat- és parancssor-szintű mintázat azonos, csak a célhive különbözik:

- **reg.exe export/save** (0023) — `Image`/`OriginalFileName` = `reg.exe` (vagy PsExec launcher), `save`/`export` kulcsszó **és** `HKLM\SECURITY` (vagy `HKLM\SYSTEM`) cél a parancssorban. A rule egyszerre fedi a .002-t és a .004-et, mert a `HKLM\SAM` és a `HKLM\SECURITY` egyaránt szerepel a `selection_target_hives` listájában — a két altechnika csak a konkrét találat céljelzőjében különül el.
- **esentutl.exe hive-másolás** (0026) — `esentutl.exe` **és** a `/system32/config/SECURITY` útvonal a parancssorban.
- **VSS-alapú hozzáférés** (0027, elsődlegesen .002-höz taggelve) — a szabály `selection_hives` mezője kifejezetten csak `\config\SAM` és `\config\SECURITY` mintát tartalmaz, tehát ténylegesen a SECURITY hive VSS-alapú elérését is elkapja, de a rule attack tagje jelenleg csak `attack.t1003.002` — ez egy valós, tag-szintű rés, lásd lent.
- **Ismert eszköznév** (0022, kiegészítő réteg) — Mimikatz `lsadump::secrets`, Impacket `secretsdump.py` nevesített futtatása.

### False positive források

- **Backup szoftver**, amely `esentutl`-t vagy VSS-útvonalat használ hive-szintű mentéshez — `SourceImage`/`ParentImage` allowlisttel szűrhető
- **Authorized backup közvetlen `reg.exe` hívással** — ritka, a legtöbb backup termék saját API-t használ, nem `reg.exe`-t
- Nincs ismert legitim ok a `HKLM\SECURITY` kézi exportjára incidenskezelésen/forenzikán kívül
