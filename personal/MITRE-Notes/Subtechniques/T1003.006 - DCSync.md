# T1003.006 — DCSync

## Lényeg

A DCSync gyökeresen más, mint a T1003 összes többi altechnikája: itt a támadó **nem fér hozzá semmilyen lemezen tárolt fájlhoz vagy hive-hoz** — ehelyett a saját gépén futó eszközzel **Domain Controllernek adja ki magát**, és a domain replikációs protokollon (MS-DRSR — Directory Replication Service Remote Protocol) keresztül kéri le tetszőleges fiók, akár a `krbtgt`, hash-eit. A DC ugyanúgy válaszol, mintha egy másik valódi DC kérné a replikációt — mert a protokoll szintjén nincs különbség.

Ehhez nem kell kód-végrehajtás a DC-n, nem kell a `ntds.dit`-hez hozzáférni — csak **Replicating Directory Changes** és **Replicating Directory Changes All** jogosultság kell a hívó fiókon. Ez a jog alapértelmezetten csak Domain Admins/Enterprise Admins/DC számítógépfiókok birtokában van, de AD ACL-hibás konfiguráció (pl. egy szolgáltatásfióknak tévedésből megadott delegált jog) miatt egy jóval alacsonyabb jogú fiók is megkaphatja — ezért a DCSync sikeres lefutása **vagy egy már kompromittált privilegizált fiókot, vagy egy korábbi AD ACL-visszaélési lépést** jelez.

> [!quote] MITRE definíció
> Adversaries may attempt to access credentials and other sensitive information by abusing a Windows Domain Controller's application programming interface (API) to simulate the replication process from a remote domain controller using a technique called DCSync.

## Hogyan csinálják a gyakorlatban

### Mimikatz lsadump::dcsync

A klasszikus, eredeti implementáció — közvetlenül az MS-DRSR-t hívja.

```
mimikatz # lsadump::dcsync /domain:corp.local /user:krbtgt
```

### DSInternals Get-ADReplAccount

A DSInternals egy aláírt, legitim PowerShell modul, amelyet AD backup és jelszó-audit célra fejlesztettek — a `Get-ADReplAccount` cmdlet ugyanazt a replikációs protokollt hívja, mint a Mimikatz, de sosem "érinti" a Mimikatzot: sem a bináris, sem a modul nem gyanús önmagában.

```powershell
Import-Module DSInternals
Get-ADReplAccount -All -Server dc01.corp.local
```

### Impacket secretsdump.py (-just-dc)

Távolról, akár Windows gép nélkül is végrehajtható; Linux-alapú red team tooling gyakran ezt választja.

```bash
secretsdump.py -just-dc corp.local/attacker:password@dc01.corp.local
```

Mindhárom eszköz azonos hálózati mintát hagy a DC-n: egy `DRSGetNCChanges` MS-DRSR hívást, amit a DC Security naplója **4662 eseményként (Directory Service Access)** rögzít, ha a megfelelő SACL be van állítva a domain objektumon — a `Properties` mezőben a replikációhoz tartozó GUID-okkal (`1131f6aa-9c07-11d1-f79f-00c04fc2dcd2` = Replicating Directory Changes, `1131f6ad-9c07-11d1-f79f-00c04fc2dcd2` = Replicating Directory Changes All).

**Mi váltja ki a gyakorlatban:** legitim oldalon két forrás van — (1) a valódi DC-k egymás közötti rendes replikációja, ami *mindig* DC számítógépfiókokból jön, és (2) dokumentált AD jelszó-audit/backup eszközök (pl. DSInternals-alapú saját szkript, PingCastle, Purple Knight), amelyek engedélyezett service accountról futnak ütemezetten.

## Mitigáció

- **Replikációs jogok szigorú auditálása és szűkítése** — ez **nem végponti kontroll, hanem AD jogosultság-kezelés**: mivel a DCSync bármely gépről indítható, csak azt lehet szabályozni, ki *kaphat* Replicating Directory Changes (All) jogot; ez az egyetlen kontroll, ami az előfeltételt ténylegesen megszünteti egy nem-privilegizált fióknál
- **SACL beállítása a domain gyökér objektumon** a replikációs GUID-okra — enélkül a natív 4662 esemény **nem generálódik**, tehát ez nem hardening, hanem a detekció **előfeltétele**: SACL nélkül a technika natívan detektálhatatlan a DC-n
- **`krbtgt` jelszó rendszeres forgatása (kétszer egymás után)** — nem akadályozza meg a DCSync-et, de csökkenti egy már megtörtént, észrevétlen DCSync **utóhatását** (golden ticket érvénytelenítése) — ez a hatás-korlátozó kategória, nem a technika megelőzése

## Detekciós stratégia

### Szükséges telemetria

| Adatforrás                          | Típus            | Megjegyzés                                                                    |
| ------------------------------------ | ---------------- | -------------------------------------------------------------------------------- |
| Sysmon EID 1 (ProcessCreate)         | Process          | A támadó gépén elinduló eszköz (DSInternals PowerShell, Mimikatz, secretsdump) — csak az *eszköz elindulását* látja, magát a replikációs kérést nem |
| **Windows Security 4662**            | Directory Access | A DC saját naplója — a `Properties` mezőben a replikációs GUID-ok; **SACL nélkül nem generálódik** |

### Detekciós logika

A .006 az egyetlen T1003 altechnika, ahol a folyamat-alapú detekció **strukturálisan nem elég**, mert a tényleges hitelesítőadat-lopás egy hálózati protokollhívás, nem egy helyi fájl-/memóriaművelet:

- **Eszköz-alapú jelzés a támadó gépén** (0029) — `Image`/`OriginalFileName` = `powershell.exe`/`pwsh.exe` **és** a `Get-ADReplAccount` cmdlet neve a parancssorban. Ez csak a DSInternals-alapú utat fedi, és csak akkor, ha a hívás a saját géples PowerShellből, nem pl. egy .NET-be ágyazott loaderből történik — a Mimikatz `lsadump::dcsync` és az Impacket `secretsdump.py -just-dc` külön nevesített ág nélkül csak a 0022 (ismert eszköznév) rétegen keresztül fut be.
- **Ismert eszköznév** (0022, kiegészítő réteg) — `lsadump::` kulcsszó a parancssorban fedi a Mimikatz DCSync-et is, de eszköznév-alapú szabályként ugyanúgy megkerülhető átnevezéssel, mint bármely más ága.
- **Natív DC-oldali detekció (4662 + replikációs GUID-ok)** — ez lenne az **egyetlen igazán megbízható jel**, mert a technika lényegét — magát a replikációs kérést — nézi, nem az azt kiváltó eszközt. Ez a repóban **jelenleg nincs megépítve** (nincs SACL-alapú Windows Security 4662 szabály).

### False positive források

- **Get-ADReplAccount** — authorizált AD jelszó-audit/higiénia-eszközök (pl. gyenge/kiszivárgott jelszó ellenőrzés NTLM hash alapján), AD disaster-recovery/backup folyamatok, biztonsági felmérő eszközök (PingCastle, Purple Knight) engedélyezett auditolás közben
- **4662 esemény (ha egyszer megépül)** — a valódi DC-DC replikáció a legfontosabb zajforrás; a hívó fiók DC számítógépfiók-e (`$` végű, `Domain Controllers` OU tag) a legmegbízhatóbb elválasztás a jogos és a jogtalan replikáció között
