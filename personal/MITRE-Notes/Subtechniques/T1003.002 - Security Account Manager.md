# T1003.002 — Security Account Manager

## Lényeg

A támadó a `HKLM\SAM` registry hive-ból nyeri ki a **helyi** felhasználói fiókok NTLM jelszó-hasheit. A SAM hive futás közben kizárólag a SYSTEM fiók számára olvasható, ezért a sikeres hozzáférés önmagában azt jelenti, hogy a támadó már rendszergazdai vagy SYSTEM jogot szerzett — ez nem privilege escalation eszköz, hanem annak eredménye.

Domain környezetben a SAM önmagában kevés értékű, mert csak helyi fiókokat tartalmaz — de mivel sok szervezet ugyanazt a helyi admin jelszót (`Administrator`) újrahasznosítja gépről gépre, egyetlen SAM kinyerése tipikusan azonnali laterális mozgást tesz lehetővé a hálózat többi, ugyanazt a jelszót használó gépe felé (pass-the-hash). A hive dekódolásához a boot key szükséges, ami a `HKLM\SYSTEM` hive-ban van — ezért a két hive szinte mindig együtt kerül kiexportálásra.

> [!quote] MITRE definíció
> Adversaries may attempt to extract credential material from the Security Account Manager (SAM) database either through in-memory techniques or through the Windows Registry where the SAM database is stored.

## Hogyan csinálják a gyakorlatban

A közös cél mindhárom módszernél ugyanaz: kimásolni a `SAM` és `SYSTEM` hive-ot (a `SECURITY` hive-ot is, ha LSA Secrets-et is visznek) úgy, hogy megkerüljék a Windows által futás közben rájuk tett kizárólagos zárolást — mert a live registry-ből ezek a hive-ok közvetlenül nem olvashatók ki egyszerű fájlmásolással.

### reg.exe export/save

A `reg.exe save` vagy `reg.exe export` a natív, beépített módszer — nincs szükség külső binárisra, ezért gyakran allowlist-ellenálló.

```powershell
reg.exe save HKLM\SAM C:\temp\sam.hiv
reg.exe save HKLM\SYSTEM C:\temp\system.hiv
```

Ez ugyanazt a `reg.exe save`/`export` parancsmintát adja, mint a LSA Secrets (T1003.004) kinyerése — a logban a `CommandLine`-ban szereplő céljelző (`HKLM\SAM` vs. `HKLM\SECURITY`) dönti el, melyik altechnikáról van szó.

### esentutl.exe /y /vss

Az `esentutl` az Extensible Storage Engine karbantartó eszköze; a `/y` (másolás) és `/vss` (Volume Shadow Copy) kombinációja lehetővé teszi zárolt fájlok másolását anélkül, hogy leállítanák a zároló szolgáltatást.

```powershell
esentutl.exe /y /vss C:\Windows\System32\config\SAM /d C:\temp\sam.hiv
```

### Volume Shadow Copy közvetlen elérés

A támadó előbb VSC-t hoz létre (`vssadmin create shadow`, WMI, vagy `diskshadow`), majd a nyers eszközútvonalon (`\\?\GLOBALROOT\Device\HarddiskVolumeShadowCopyN\Windows\System32\config\SAM`) másolja ki a fájlt bármilyen eszközzel (`copy`, `robocopy`, `certutil`, PowerShell). A CVE-2021-36934 (HiveNightmare / SeriousSAM) hibás ACL-je miatt ez a hozzáférés egy ideig **nem-admin** felhasználók számára is működött a VSC-másolatokon.

```powershell
copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\Windows\System32\config\SAM C:\temp\sam.hiv
```

A kimásolt hive-okból a hash-eket ezután tipikusan másik gépen, offline nyerik ki: Impacket `secretsdump.py`, `pypykatz`, vagy Mimikatz `lsadump::sam`.

**Mi váltja ki a gyakorlatban:** legitim IT-oldalon szinte kizárólag tervezett incidenskezelési/forenzikus vizsgálat vagy hive-szintű biztonsági mentés hozza létre ugyanezt a mintát — normál üzemeltetés soha nem exportálja kézzel a SAM hive-ot.

## Mitigáció

- **A helyi admin jogok korlátozása** — mivel a hozzáféréshez már SYSTEM/admin szint kell, ez nem a technikát állítja meg, hanem az előfeltételét szűkíti; a legtöbb környezetben ez a leghatékonyabb egyetlen kontroll
- **LAPS (Local Administrator Password Solution)** — nem akadályozza meg a SAM kinyerését, de **értéktelenné teszi a zsákmányt**, mert minden gépen egyedi a helyi admin jelszó — ez direkt hatással van arra, hogy a szabály találata mennyire súlyos esemény egy adott környezetben
- **CVE-2021-36934 patch** — a hibás VSC ACL javítása után a nem-adminút megszűnik, de az admin/SYSTEM jogú export továbbra is működik — ez nem szünteti meg a szabály relevanciáját, csak az egyik (alacsonyabb jogú) belépési pontot zárja be

## Detekciós stratégia

### Szükséges telemetria

| Adatforrás                   | Típus   | Megjegyzés                                                             |
| ----------------------------- | ------- | ----------------------------------------------------------------------- |
| Sysmon EID 1 (ProcessCreate)  | Process | `reg.exe save/export`, `esentutl.exe /y /vss`, VSS eszközútvonal a CommandLine-ban |
| Sysmon EID 11 (FileCreate)    | File    | A kiírt `.hiv`/`sam` másolat megjelenése (jelenleg nincs rá dedikált szabály ebben a repóban) |

### Detekciós logika

- **reg.exe export/save** (0023) — `Image` vagy `OriginalFileName` = `reg.exe`, `CommandLine` tartalmaz `save`/`export` kulcsszót **és** `HKLM\SAM`/`HKLM\SECURITY`/`HKLM\SYSTEM` célt. A PsExec `-s` flaggel indított `reg.exe` gyermekfolyamatot is lefedi, és a PsExec launcher parancssorát is (ha a gyermek-telemetria hiányos).
- **esentutl.exe hive-másolás** (0026) — `Image`/`OriginalFileName` = `esentutl.exe`, `/y` másoló kapcsoló **és** a hive fájl konkrét útvonala (`/system32/config/SAM` stb.) a parancssorban.
- **VSS-alapú hozzáférés** (0027) — eszközfüggetlen: bármely folyamat parancssorában együtt szerepel a `HarddiskVolumeShadowCopy` minta **és** a `\config\SAM`/`\config\SECURITY` útvonal. Ez fogja meg a CVE-2021-36934-et is, mert a mintázat privilégiumszinttől függetlenül azonos.
- **Ismert eszköznév** (0022, kiegészítő réteg) — a [[T1003.001 - LSASS Memory]] jegyzetben leírtakkal megegyezően: Mimikatz `lsadump::sam`, Impacket `secretsdump.py` stb. nevesített futtatása. Önmagában soha nem elég, mert átnevezéssel megkerülhető.

### False positive források

- **Backup szoftver**, amely `esentutl`-t vagy VSS-útvonalat használ hive-szintű rendszerállapot-mentéshez — a `SourceImage`/`ParentImage` allowlistelése oldja meg
- **Offline AD DS karbantartás** (defragmentáció, integritás-ellenőrzés) — ritka, mindig leállított AD DS-t és dokumentált change controlt igényel
- Nincs ismert legitim ok arra, hogy valaki kézzel exportálja a `HKLM\SAM`-ot incidenskezelésen/forenzikán kívül — ez a 0023 és 0027 leggyakoribb tuning-forrása marad az allowlist karbantartása
