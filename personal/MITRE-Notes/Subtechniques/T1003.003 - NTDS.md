# T1003.003 — NTDS

## Lényeg

A támadó a Domain Controller `%SystemRoot%\NTDS\ntds.dit` fájljából — az Active Directory saját ESE (Extensible Storage Engine) adatbázisából — nyeri ki a **teljes domain** összes felhasználói és gépi fiókjának hash-ét egyszerre. Ez a T1003 legmagasabb hozamú altechnikája: egyetlen fájl a teljes domain hitelesítőadat-készletét tartalmazza, beleértve a `krbtgt` fiókot is, amivel golden ticket készíthető.

A művelethez Domain Controller admin jog kell, tehát ez már a domain-szintű teljes kompromittálódás egyik utolsó lépése. A `ntds.dit` futás közben az ESE motor által kizárólagosan zárolt fájl, ezért minden módszer közös eleme valamilyen módon **megkerülni ezt a zárolást** — VSS-en, IFM-en, vagy a fájlrendszer alacsony szintű olvasásán keresztül.

> [!quote] MITRE definíció
> Adversaries may attempt to access or create a copy of the Active Directory domain database in order to steal credential information, as well as obtain other information about domain members such as devices, users, and access rights.

## Hogyan csinálják a gyakorlatban

### ntdsutil IFM (Install From Media)

A leggyakoribb natív módszer: a támadó aktiválja az NTDS instance-t, majd egy önálló, offline felhasználható másolatot készíttet a `ntds.dit`-ről és a SYSTEM hive-ról.

```
ntdsutil.exe "ac i ntds" "ifm" "create full C:\temp\ntds_dump" quit quit
```

Az `ac i ntds` (activate instance ntds) rövid és hosszú formája egyaránt előfordul, a `create full` mindig együtt jár vele.

### esentutl.exe VSS/másolás

Az ESE karbantartó eszköz `/vss` vagy `/y` kapcsolóval közvetlenül másolja a zárolt fájlt.

```powershell
esentutl.exe /y /vss C:\Windows\NTDS\ntds.dit /d C:\temp\ntds.dit
```

### Volume Shadow Copy manuális útvonal

`vssadmin create shadow`, WMI, vagy `diskshadow.exe` (script módban, `/s` kapcsolóval) hoz létre egy VSS pillanatképet, amiről a támadó közvetlenül másolja ki a `ntds.dit`-et bármilyen eszközzel (`xcopy`, `robocopy`, `cmd.exe /c copy`).

```powershell
diskshadow.exe /s C:\temp\dump_ntds.txt
copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\Windows\NTDS\ntds.dit C:\temp\ntds.dit
```

### wbadmin.exe (Windows Server Backup)

A `wbadmin` teljes rendszerállapot-mentés (system state backup) részeként visszaállítja/kimenti a `ntds.dit`-et — a `-include:`/`-items:` paraméterben a forrás útvonal közvetlenül szerepel, eltérően a VSS-alapú módszerektől, ahol a célfájl csak implicit.

### Közvetlen élő útvonal másolása

Ha a támadó le tudja állítani az AD DS szolgáltatást, a `ntds.dit` a natív helyéről közvetlenül másolható — ez a legritkább, de a legdirektebb út.

### Underlay-Copy (alacsony szintű NTFS kinyerés)

Az `Underlay-Copy` PowerShell cmdlet az MFT-t közvetlenül elemezve, vagy `fsutil` metaadat-olvasással másolja a zárolt fájlt — soha nem hoz létre Volume Shadow Copy-t, és nem hív `cmd.exe copy`-t sem, ezért mind a VSS-alapú, mind a közvetlen-másolás alapú detekciót megkerüli.

```powershell
Import-Module UnderlayCopy
Underlay-Copy -Path C:\Windows\NTDS\ntds.dit -Destination C:\temp\ntds.dit -Mode MFT
```

A kinyert `ntds.dit` + a SYSTEM hive boot key birtokában a hash-eket offline fejtik: Impacket `secretsdump.py`, DSInternals, vagy Mimikatz `lsadump::lsa`.

**Mi váltja ki a gyakorlatban:** a legtöbb ág legitim oldalon kizárólag tervezett DC-provisioning (IFM média új DC-hez), offline AD adatbázis-karbantartás, vagy dokumentált backup/disaster-recovery folyamat során fordul elő — ezek mindegyike ritka és bejelentett esemény egy jól kezelt környezetben.

## Mitigáció

- **A Domain Controllerekhez való adminisztratív hozzáférés szigorú korlátozása (Tiering, PAW)** — mivel a technika DC admin jogot igényel, ez az egyetlen kontroll, ami ténylegesen megszünteti az előfeltételt, nem csak megnehezíti
- **Fájlrendszer-titkosítás (BitLocker) a DC lemezén** — nem akadályozza meg az online kinyerést (a futó rendszeren a fájl dekódolva érhető el), csak a lemez fizikai ellopása elleni védelem — nem releváns e szabálycsalád szempontjából
- **Backup jogosultságok szűkítése** (`Backup Operators` csoporttagság auditálása) — a wbadmin- és VSS-alapú ágak előfeltétele; ha ez a csoport üres/szűk, azok az ágak gyakorlatilag lezárva maradnak

## Detekciós stratégia

### Szükséges telemetria

| Adatforrás                  | Típus   | Megjegyzés                                                                 |
| ---------------------------- | ------- | ---------------------------------------------------------------------------- |
| Sysmon EID 1 (ProcessCreate) | Process | `ntdsutil`, `esentutl`, `diskshadow`, `wbadmin`, VSS-eszközútvonal a parancssorban |
| Sysmon EID 11 (FileCreate)   | File    | A kiírt `ntds.dit`-másolat megjelenése (jelenleg nincs rá dedikált szabály)  |

### Detekciós logika

Egyetlen szabály (0024) hét, egymást kiegészítő ágon fedi a fő módszereket, mert egy tool-lista soha nem lenne kimerítő:

1. **ntdsutil IFM** — `Image`/`OriginalFileName` = `ntdsutil.exe` **és** a parancssorban `ac i ntds`/`activate instance ntds` **és** `create full` együtt.
2. **esentutl VSS/másolás** — `esentutl.exe` **és** a `\windows\ntds\ntds.dit` célútvonal a parancssorban.
3. **VSS-alapú kinyerés bármely eszközzel** — `HarddiskVolumeShadowCopy` string **és** `ntds.dit` együtt a parancssorban, eszközfüggetlenül.
4. **diskshadow script mód** — `diskshadow.exe` **és** `/s ` kapcsoló (interaktív munkamenet nem igényel script fájlt).
5. **wbadmin NTDS célzás** — `wbadmin.exe` **és** `\windows\ntds` útvonal a parancssorban.
6. **Közvetlen élő útvonal másolása** — `/c copy ` **és** `\windows\ntds\ntds.dit` együtt; akkor is jelez, ha AD DS fut és a másolás ténylegesen sikertelen, mert a *szándék* már ekkor látszik.
7. **Ismert NTDS dump eszköz** — `NTDSDump.exe`/`NTDSDumpEx.exe` néven vagy `OriginalFileName`-ben, vagy a `ntds.dit` + `system.hiv` CLI-fingerprint, vagy `NTDSgrab.ps1`.

Ezt egészíti ki két, kifejezetten **evázió-ellenes** szabály:

- **Symlink a VSS eszközútvonalra** (0030) — ha a támadó `mklink` vagy PowerShell `New-Item -ItemType SymbolicLink/Junction`-nel egy symlinket hoz létre a `HarddiskVolumeShadowCopy` eszközútvonalra, minden további fájlművelet már a symlinken keresztül megy — a nyers VSS útvonal soha többé nem jelenik meg a parancssorban, így a 3. és 6. ág fentebb kicsúszik alóla. Ez a szabály magát a symlink-létrehozást fogja meg, nem az azt követő olvasást.
- **Underlay-Copy / alacsony szintű NTFS kinyerés** (0031) — a `Underlay-Copy` cmdlet nevét keresi **és** a `ntds.dit`/SAM/SECURITY/SYSTEM célt; ez az egyetlen ág, ami se VSS-t, se `cmd.exe copy`-t nem használ, ezért a fenti két detekciós felület egyikét sem érinti.

### False positive források

- **ntdsutil IFM** — legitim DC-provisioning és IFM média készítés; csak ismert admin fiókoktól, tervezett DC-telepítés/csere során várható
- **esentutl / offline karbantartás** — ritka, mindig leállított AD DS-t és dokumentált change controlt igényel
- **VSS + ntds.dit útvonal** — backup szoftver (Veeam, Windows Server Backup), amely a shadow copy útvonalat a parancssorban is felfedi — `ParentImage` allowlisttel szűrhető
- **diskshadow /s** — backup- és tárolóautomatizálási szkriptek, amelyek diskshadow-ot NTDS-tól független lemezkezelési feladatra használnak
- **wbadmin** — legitim offline AD DS backup/recovery, dokumentált change management alatt
- **Közvetlen élő útvonal másolása** — nincs ismert legitim ok, minden találat azonnali vizsgálatot érdemel
- **Symlink VSS eszközútvonalra / Underlay-Copy** — gyakorlatilag nincs ismert legitim felhasználás egyik ágra sem; a szűk kivétel a forenzikus eszközök dokumentált IR-forgatókönyve
