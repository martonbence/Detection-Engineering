# T1505.003 — Web Shell

## Lényeg

A támadó egy kis szerveroldali szkriptet (a *web shellt*) helyez el egy webről elérhető könyvtárba, és ezen keresztül tartós, interaktív hozzáférést kap a szerverhez — miközben kifelé minden forgalom sima HTTP marad. A web shell nem exploit: ez a **következmény**, amit egy korábbi kihasználás ([[T1190 - Exploit Public-Facing Application]]) vagy egy sérülékeny feltöltési pont lehetővé tett. A [[T1505 - Server Software Component]] alá azért tartozik, mert a web shell a webszerver saját, legitim futtatási képességét (PHP/ASP/JSP interpreter) fordítja perzisztenciává.

A támadó nyeresége kettős. Egyrészt **perzisztencia**: a fájl a lemezen marad, túléli az újraindítást, és nem függ attól, hogy az eredeti exploit még működik-e. Másrészt **álca**: a web shell forgalma ugyanazon a 443/80-as porton, ugyanabban a folyamatban zajlik, mint a legitim webforgalom — nincs külön C2-csatorna, amit egy hálózati szabály megfogna.

> [!quote] MITRE definíció
> Adversaries may backdoor web servers with web shells to establish persistent access to systems. A Web shell is a Web script that is placed on an openly accessible Web server to allow an adversary to access the Web server as a gateway into a network.

## Hogyan csinálják a gyakorlatban

Egygépes szempontból nézve minden a webszerver-hoston történik, de a web shell életciklusa **két, időben elváló fázisra** bomlik, és detekciós szempontból pont ez a szétválás a lényeg: az egyik fázis rutinszerű, a másik a tényleges jel.

### 1. fázis — a shell elhelyezése (upload / írás)

A fájl vagy egy sérülékeny feltöltési funkción keresztül kerül fel (a feltöltés-validáció megkerülésével), vagy egy korábbi kihasználás írja a webroot alá. A feltöltés-szűrő megkerülésének klasszikus alakjai a **dupla kiterjesztés** (a fájlnév végén futtatható kiterjesztés egy ártalmatlannak látszó után, pl. `.php.jpg`), a **trailing-dot** és a **null-byte** variánsok. A repo emulációs tesztje ezt a benign alakban gyakorolja: egy ártalmatlan fájlt tesz egy `uploads/` könyvtárba, majd POST-tal és GET-tel megcímzi — a lényeg a *minta*, nem a tartalom.

Ez a fázis önmagában **rutin webforgalom**: egy feltöltés-funkcióval rendelkező alkalmazáson percenként érkezhet legitim POST. Emiatt az upload puszta jelenléte nem jel.

### 2. fázis — a shell aktiválása / vezérlése

A támadó ezután a felkerült szkriptet **meghívja** — vagy egyszerűen csak visszatölti (GET a most feltöltött URL-re), vagy paraméterben adja neki ki a parancsot. Ez utóbbi az, ami a query stringen keresztül látszik: egy már elhelyezett shell parancs-interfésze, ahol a paraméter értéke egy operációs rendszer parancs vagy egy közvetlen kód-végrehajtási indikátor. A repo emulációs tesztje ezt is benign alakban végzi (`?x=whoami` a default nginx oldal ellen).

**Mi váltja ki a gyakorlatban:** a web shell aktiválásának nincs jóindulatú megfelelője a szó szoros értelmében — de a *jelet* kiválthatja legitim forgalom. Egy feltöltési widget bevett UX-mintája, hogy a feltöltés után a kliens azonnal visszatölti (GET) a most feltöltött fájlt (előnézet, megerősítés); egy alkalmazás, ami `cmd=`/`exec=` paramétert használ nem-shell célra (`cmd=view`, `cmd=export`); vagy egy wiki/dokumentációs oldal, aminek a keresésében operációs rendszer parancsnév szerepel. Ezek adják a szabályok valódi FP-felületét.

## Mitigáció

A MITRE két mitigációt sorol, és mindkettő közvetlenül a detekció hatókörét magyarázza:

- **Veszélyes függvények letiltása (M1042).** PHP-nál az `eval()`-szerű dinamikus kód-végrehajtó függvények kikapcsolása (pl. `disable_functions`) elveszi a web shell mögötti mechanizmust. Ahol ez érvényben van, ott a `DETECT-2026-0040` `selection_direct_indicator` ágának `eval(`/`system(` mintája **kevésbé releváns** — a shell nem tudná végrehajtani. Vagyis ez a kontroll megmondja, mely környezetben számít egyáltalán a query-string-alapú parancsvégrehajtás detekciója.
- **Legkisebb jogosultság a webkönyvtáron (M1018).** Ha a webszerver folyamata nem tud írni a saját kiszolgált könyvtárába, az 1. fázis (a fájl elhelyezése) eleve meghiúsul. Ez a `DETECT-2026-0039` upload-detekciójának a kontextusa: ahol a webroot írásvédett, ott a feltöltés-alapú perzisztencia nem működik, és a szabály relevanciája a nem-írásvédett (pl. dedikált `uploads/`) útvonalakra szűkül.

Amit tudatosan kihagyunk: a generikus "tartsd naprakészen a CMS-t" jellegű tanácsot — igaz, de nem köt vissza ahhoz, mit lát vagy nem lát a két access-log-szabály.

## Detekciós stratégia

### Szükséges telemetria

| Adatforrás | Típus | Megjegyzés |
| ---------- | ----- | ---------- |
| nginx access log (`access_combined`) | Web | `method`, `uri_path`, `uri_query`, `status`, `bytes`, `clientip`. A repo egyetlen forrása; se request body, se response body |
| Web szerver folyamat-telemetria (Sysmon EID 1) | Process | Az `nginx`/`w3wp.exe`/`httpd` gyermek-shellt vagy interpretert indít — a MITRE saját analitikáinak (AN1108/AN1109/AN1110) **elsődleges** jele. Ebben a repóban hiányzik |
| Web szerver fájlírás (Sysmon EID 11) | File | A webroot alá írt új `.php`/`.jsp`/`.aspx` — a legdirektebb "shell elhelyezve" jel. Hiányzik |

### Detekciós logika

A meghatározó tény: **az access log a shellt csak a HTTP-kérésen keresztül látja, a fájlrendszeren és a folyamat-fán soha.** Ezért mindkét repo-szabály a *forgalmi* lenyomatra épül, nem a MITRE által elsődlegesnek nevezett fájl-/folyamat-jelre — az adatforrás határa, nem hangolási kérdés.

- **`DETECT-2026-0039` — a feltöltés-aktiválás párosítás.** Az önálló upload rutin, ezért a szabály **két eseményt köt össze**: egy futtatható/dupla-kiterjesztésű fájlra irányuló POST-ot (kis vagy ismeretlen válaszmérettel, 200/201) és egy ugyanarról a `clientip`-ről, ugyanarra az `uri_path`-ra érkező GET-et 15 percen belül. Ez a párosítás a tényleges jel: "feltöltöttek valamit, majd meg is hívták." Sigma `detection:` blokk nem tud időablakos, kétesemény-join-t kifejezni (nincs `correlation:` a repo sémájában), ezért a valódi logika `custom.splunk.raw_query`-ben él, `streamstats` carry-forward join-nal — ugyanaz az escape hatch, mint a 0002/0003 korrelációknál.
- **`DETECT-2026-0040` — a már elhelyezett shell vezérlése.** Egyesemény-minta: GET + 200 + a query stringben egy Linux post-exploitation parancs-artefaktum. Három alakja van: (1) bare parancs-/binárisnév paraméter-értékként, kötelező terminátorral (hogy a név a *teljes* érték legyen, ne a prefixe); (2) `cmd=`/`exec=`/`command=` paraméter, egy megerősítő shell-metakarakterhez vagy token-lehorgonyzott ismert binárishoz kötve — **nem a paraméternév önmagában**; (3) közvetlen kód-végrehajtási indikátorok, amelyeknek nem kell megerősítés. A 2. és 1. alakot 2026-09-26-án szigorították, miután a felülvizsgálat két rendszerszintű FP-osztályt talált: a lehorgonyzatlan binárisnevek `cmd=publish`/`cmd=finance`/`cmd=catalog`-ra is elsültek, és a `&` query-elválasztót tévesen "shell-metakarakterként" kezelte.
- **Tudatosan nem detektált:** a POST-bodyban végrehajtott parancs (pl. China Chopper — nincs body a logban), és a base64/obfuszkált/string-konkatenált parancs (statikus minta-illesztés a query stringen nem éri el). Mindkettő a `DETECT-2026-0040` nevesített vakfoltja.

### False positive források

- **Feltöltés-widget UX-mintája (0039).** A feltöltés utáni azonnali visszatöltő GET jóindulatú — a szabály a futtatható-kiterjesztés-kapuval szűri, de egy CGI/Perl-alapú form-handler `.cgi`/`.pl` fájlja + a kliens megerősítő GET-je párként fennakadhat.
- **`cmd=`/`lang=` legitim használat (0040).** Egy `?lang=python` vagy `?cmd=view` az access-log szintjén megkülönböztethetetlen a shell-hívástól; a szabály a bare-név ágnál ezt tudatosan elfogadja, mert a legtöbb valódi webshell-interakció alakját (a bare parancsnév) elvetni túl drága lenne.
- **Saját scanner/upload-fuzzer.** Burp Intruder, `ffuf`, upload-bypass tooling upload+GET párt replaying-el — a scan-naptárral kell összevetni.
- **Nevesített scope-korlátok (0039), nem logikai hibák:** a join azonos `uri_path`-ot kíván (átírt/hashelt/CDN-frontolt visszatöltési URL nem párosul); az upload-könyvtár gate csak `uploads?`/`files?`/`file-manager`/`tmp`-t fogad (a `/media/`, `/assets/`, téma-mappa kicsúszik); a trailing-dot/null-byte kiterjesztés-variánsok nem illeszkednek.
