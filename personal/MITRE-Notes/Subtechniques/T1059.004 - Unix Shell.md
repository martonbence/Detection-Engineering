# T1059.004 — Unix Shell

## Lényeg

A támadó Unix shell parancsokat és szkripteket futtat kódvégrehajtásra. A Unix shell (`sh`, `bash`, `zsh`, `ash`/BusyBox stb.) a Linux, macOS és ESXi rendszerek elsődleges parancssori felülete — ugyanaz a szerep, mint amit a Windows-oldalon a PowerShell ([[T1059 - Command and Scripting Interpreter]] `.001`) tölt be, és a repóban is ez a párhuzam a legbeszédesebb: a PowerShell-család 12 szabálya a Windows-végponti kódfuttatás gerince, ez az egyetlen `.004`-es szabály pedig a Unix-oldali megfelelő — csak nagyságrendekkel kisebb lefedettséggel, mert a repóban nincs Linux-végponti telemetria.

A shell azért kitüntetett a támadónak, mert **mindenütt ott van és mindent tud**: nincs szükség külön eszközre, a shell maga tud fájlt letölteni (`curl`/`wget`), hálózati kapcsolatot nyitni (`/dev/tcp`), interpretert indítani, jogosultságot vizsgálni. Egy megszerzett kódfuttatás első lépése szinte mindig egy shell megnyitása.

> [!quote] MITRE definíció
> Adversaries may abuse Unix shell commands and scripts for execution. Unix shells are the primary command prompt on Linux, macOS, and ESXi systems, though many variations of the Unix shell exist (e.g. sh, ash, bash, zsh, etc.) depending on the specific OS or distribution.

## Hogyan csinálják a gyakorlatban

Egygépes technika a klasszikus esetben (a shell a kompromittált gépen fut), de a repo szempontjából fontos egy megkülönböztetés: **hol látszik a shell-parancs**. Két, teljesen eltérő megfigyelési pont van.

### Natív végponti shell-futás (a repóban NEM látható)

A tényleges Unix-oldali kódfuttatás a gépen zajlik: a támadó `bash`/`sh`/`zsh` folyamatot indít — remote session-ből, jogosulatlan felhasználóként, vagy egy másik interpreterből beágyazva. A MITRE saját analitikái (AN1081–AN1084) épp ezt a láncolt viselkedést nevezik meg jelként: shell egy szokatlan szülőből, szokatlan kontextusban.

Ez a réteg **ebben a repóban tudatosan nincs felépítve** — nincs Linux-végponti folyamat-telemetria (auditd/EDR). Ezért a repo egyetlen `.004`-es szabálya nem is innen jön.

### Web shell parancs-interfészén át (amit a repo lát)

A repo a `.004`-et **közvetve**, a webszerver access logján keresztül látja: amikor egy már elhelyezett web shellt ([[T1505.003 - Web Shell]]) a query stringjén keresztül vezérelnek, a beadott érték egy Unix parancs — `whoami`, `uname`, `wget`/`curl`, vagy közvetlen kód-végrehajtási/reverse-shell indikátor (`/dev/tcp/`, `system(`). Ez a shell-parancs *artefaktuma* a HTTP-kérésben, nem a `bash` folyamat maga — a szerveren már lefutott (vagy le fog futni), de amit a repo lát, az a kérés, nem a végrehajtás.

Ezért visel a `DETECT-2026-0040` **egyszerre** `attack.t1505.003`-at és `attack.t1059.004`-et: a T1505.003 a mechanizmus (a web shell, mint perzisztens komponens), a T1059.004 pedig a rajta keresztül végrehajtott dolog (Unix shell parancs). A repo-konvenció szerint ez helyes kettős tag — a szabály logikája mindkét technikát valóban megtestesíti, nem az egyik alá van kényszerítve.

**Mi váltja ki a gyakorlatban:** natív oldalon a shell-futásnak nincs értelmes jóindulatú/rosszindulatú megkülönböztetése önmagában — a `bash` percenként ezerszer indul egy Linux gépen legitim okból, ez a technika alacsony fidelitásának a gyökere. A web-oldali ágnál a *jelet* kiváltó jóindulatú forgalom egy olyan alkalmazás, ami parancsnevet fogad paraméterként nem-shell célra (`?lang=python`, `?cmd=view`), vagy egy dokumentációs oldal, aminek az URL-jében parancsnév szerepel.

## Mitigáció

A MITRE egyetlen mitigációt sorol ehhez az altechnikához, és annak a repo-relevanciája korlátozott:

- **Végrehajtás-megelőzés / alkalmazás-kontroll (M1038).** Linuxon a shell futtatásának korlátozása alkalmazás-kontrollal ritka és nehéz — a shell a rendszer alapvető része, nem "eltávolítható" komponens, hasonlóan a Windows-oldali `pktmon`/`netsh` helyzetéhez [[T1040 - Network Sniffing]]-nél. ESXi-n a MITRE kifejezetten említi az `execInstalledOnly` funkciót (csak aláírt VIB-csomagból származó binárisok futhatnak) — ez a repo hatókörén kívül esik. **Gyakorlati következmény:** a shell-futás megelőzése ezen a technikán nem reális elsődleges védelem, ezért a detekció súlya nagyobb — de épp ez az, ami a repóban natív oldalon hiányzik.

Amit kihagyunk: a generikus "korlátozd a felhasználói jogosultságokat" tanácsot — igaz, de nem köti vissza a `DETECT-2026-0040` konkrét, web-oldali detekciós hatóköréhez.

## Detekciós stratégia

### Szükséges telemetria

| Adatforrás | Típus | Megjegyzés |
| ---------- | ----- | ---------- |
| Linux végponti folyamat-telemetria (auditd / EDR) | Process | A `bash`/`sh`/`zsh` folyamatindítás szülő-kontextussal — a MITRE elsődleges jele (AN1081–AN1084). **Ebben a repóban nincs**, ez a natív, közvetlen forrás lenne |
| nginx access log (`access_combined`) | Web | Csak *közvetve*: a web shell query stringjében megjelenő Unix parancs-artefaktum. Ez a repo egyetlen tényleges forrása erre az altechnikára |

### Detekciós logika

A kulcstény: **a repo a Unix shell-futást soha nem közvetlenül látja.** A natív jel (a `bash` folyamat a Linux végponton) hiányzik, mert nincs Linux-végponti telemetria. Amit lát, az a web shell parancs-interfészének HTTP-lenyomata — vagyis a `.004` detekciója itt teljes egészében a `.003` detekcióján lovagol.

- **A `DETECT-2026-0040` a query stringben keres Unix parancs-artefaktumot** (részletes logika: [[T1505.003 - Web Shell]] Detekciós logika szakasza). A `.004`-szempontból a lényeg, hogy a keresett minták Linux-parancs-flavorúak (`whoami`, `uname`, `wget`, `curl`, `/dev/tcp/`, `system(`) — ez a SigmaHQ `web_win_webshells_in_access_logs.yml` szabályának a *Linux-megfelelője*: az a szabály Windows-parancs-ízű (`=whoami`, `=net user`, `=cmd /c`), ez pedig a Unix-oldali párja, amit Masha nginx gap-elemzése hiányzóként jelzett.
- **Amit ez a megközelítés nem lát:** a POST-bodyban végrehajtott parancsot (China Chopper), az obfuszkált/base64/string-konkatenált parancsot, és — a legfontosabb — a **teljes natív oldalt**: bármilyen shell-futás, ami nem egy web shell query stringjén keresztül érkezik, teljesen láthatatlan. Egy SSH-n bejelentkező támadó `bash` parancsairól ez a repo semmit nem tud.

### False positive források

- **Parancsnevet nem-shell célra használó paraméter.** `?lang=python`, `?cmd=view`, `?cmd=export` — access-log szinten megkülönböztethetetlen a shell-hívástól. A `DETECT-2026-0040` a bare-név ágnál ezt tudatosan elfogadja (a valódi webshell-interakció leggyakoribb alakja is bare parancsnév), a `cmd=` ágnál viszont megerősítő metakaraktert vagy token-lehorgonyzott binárist követel, így a `cmd=view` nem sül el.
- **Dokumentációs/wiki oldal parancsnévvel az URL-ben.** Egy Linux-tutorial URL-je, ami `whoami`-t tartalmaz — a forrás-szabály production-hangolása ezt elég ritkának találta ahhoz, hogy elfogadja.
- **Prefix-ütközések kizárva.** A kötelező terminátor miatt `auth=sshkey`, `pkg=perlbrew`, `url=curl.se`, `q=telnetd` nem sülnek el — csak az illeszkedik, ahol a parancsnév a teljes token.
