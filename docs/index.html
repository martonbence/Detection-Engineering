Legend & how this page works
Verdicts — what the CI pipeline found
PASS The Atomic Red Team test ran and the Splunk detection fired. FAIL The test ran to completion and no alert fired — a confirmed negative. Also covers the cases where the rule itself is at fault: the saved search isn't in Splunk, or the search errored when Splunk ran it. NOT VERIFIED Deployed and attempted, but something didn't finish — so nothing is known either way. Unknown, not broken. Two routes reach it: the attack didn't complete (the Atomic Red Team run was cut short by its timeout), or the measurement didn't complete (the Splunk search never finished, or the query errored on the way). The first only applies to rules tested by Atomic Red Team — for an Emulation-verified rule (see Verification below) a test that never started still reads as a FAIL, because all the pipeline sees is an absence of events. The second applies to every rule, however it is tested. N/A Never tested — no test result exists for this rule.
A verdict badge links to the GitHub Actions run it came from, and the rule's drawer shows when it was last tested.
Evidence — whether that verdict still holds
A verdict is a certificate: it stops being evidence about the rule as it stands either because the rule changed underneath it, or because it simply got old. Both mean the same thing — we do not know today — and both are fixed by the same thing, a re-run. So neither counts toward the Pass Rate, and a badge in either state is drawn hollow. The marker beside it says which happened.
PASS Superseded. Measured on an earlier version of the rule — the logic has changed since, so the badge describes text that is no longer there. The certain case: what was tested is provably not what is deployed. Independent of age, a rule edited this morning is superseded even if it passed yesterday. PASS● Expired. Same logic as when it was tested, but the verdict is older than 180 days. The probabilistic case: nothing in the rule moved, but telemetry, Splunk config and attacker tooling may have. The age is measured against your clock as you read this, so a rule crosses the line on its own between pipeline runs — and the Pass Rate above the chart is recomputed with it.
The Verdict → Evidence filter splits the library on exactly this: Current, Superseded, Expired, Never tested — and the Evidence chart on the Dashboards tab is the same four values as a ring. Expired is simply not drawn while nothing has expired.
A rule's version comes from its commit history, so any edit to the file supersedes its verdict — a re-worded description counts the same as re-written logic. That is deliberately blunt: it can only ever overstate how much needs re-testing, never understate it.
Lapsing is a correction to the numbers, not a gate. Nothing in the pipeline blocks a rule from staying in production on a verdict that no longer holds; this page is where you find out.

MITRE Navigator
Covered technique. The coloured left rail is the best verdict among the rules mapped to it — green PASS, amber NOT VERIFIED, red FAIL, grey N/A. A sub-technique carries the same verdict as a dot instead of a tint. Parent techniques get the tint. No rule maps to this technique — a gap. The technique itself has no rule, but one or more of its sub-techniques does. The n/m badge counts them; expand the cell to see which. At least one rule covering this technique FAILed, even though the cell shows a better verdict. On a parent cell the flag can be inherited from a sub-technique. Hover the cell for the rule list.
Verdict and Covered / Gaps answer different questions: Covered/Gaps is whether a detection exists at all, Verdict is how the existing ones performed. They combine, so Gaps plus any verdict is deliberately empty.
Hover a cell for its rules, click ☰ for the detail panel, and use the tactic header caret to collapse a column. Export view writes out exactly what the current filters show.
The same menu's ATT&CK Navigator JSON is a different thing: the full coverage as a standard layer file. Load it into the official MITRE Navigator (Open Existing Layer → Load from URL) to compare this coverage against another layer — a threat actor's technique set, a red team's results, an earlier snapshot. Techniques whose covering rules include a failure are marked ⚠ there too.
Dashboards
Rule Overview breaks the library down by type, severity, status and verification outcome. MITRE ATT&CK Alignment shows overall technique coverage and how the rules spread across tactics. Trends Over Time tracks coverage and rule count from the repo's own history — one data point per day the pipeline ran, so gaps in the line are days with no run.
Evidence and Verification are two rings because they are two questions, and a slice can only carry one name. Evidence asks how much of the library has a verdict worth reading — all 27 rules, split into Current / Superseded / Expired / Never tested. Verification asks what those readable verdicts actually say, and counts only the current ones, so its ring is the Current slice of the one beside it, not the whole library. A lapsed PASS is not a pass that happens to be old — it is an absence of present-tense evidence, so it is counted once, on the left, and never as a pass on the right.
Read the two together: Pass Rate says how much of what was measured works, Current how much of the library was measured. Alone, either one flatters. Both are recomputed in your browser on every load, so they stay true as verdicts age past the review interval after this page was built — and Verification Age is the distribution behind Evidence's Expired slice.
Legend entries are clickable: they toggle their series in and out of the chart.
